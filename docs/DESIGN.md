# MetaFor design context

## Existing visual direction

The application uses light mode only. The navbar has no theme switch, and Nuxt UI color-mode management is disabled in vite.config.js so saved preferences and system dark mode do not change the application palette. Existing dark CSS remains dormant.

MetaFor uses a calm journal-like interface for personal mood reflection. Keep the current warm neutral surfaces, terracotta primary color, and restrained lavender accent. Raleway owns headings and controls; Crimson Text owns prose. The shared rules for every page (tokens, type scale, layout, components) are in `STYLE.md`. Runtime color and type tokens live in `client/src/assets/css/main.css`; Nuxt UI components consume those tokens.

The Daily Mood screen uses a single writing column, up to 820px wide. Past entries switches to an in-page history view while preserving the unsaved draft. Saved reflections reuse the editor’s ruled paper, ink, and Biro Script handwriting; Date and mood sit inside each sheet in journal handwriting, with a small ink-drawn face and an explicit mood label. MoodFace.vue owns the shared drawings for history and mood buttons. Button hover and keyboard focus reveal distinct expressions: Happy smiles with gently curved eyes and a small head tilt; Sad closes its eyes with a falling tear; Relaxed sighs; Anxious looks side to side; Angry furrows and shakes. Reactions play once, hold the expression while hovered, and reset on exit. Reduced motion keeps the expression change without animated movement. The history view has its own page title and uses normal page scrolling. A purple sparkle launcher appears inside the notebook once writing begins or the field is focused. It opens a small Nuxt UI popover with a MetaFor Helper heading, prompt field, and action; AI requests still send only that explicit prompt. Generated starters are added only by the user. Saved drawings appear as paper-clipped sticky notes on their original entry, using the same shared canvas renderer as the editor. Notes can be dragged within the notebook or moved using arrow keys on the focused drag handle; positions are temporary and reset on reload or when the notebook width changes. Viewing them never replaces the current draft. The drawing canvas stays visible below the writing field, above the save action. Preserve the notebook treatment and existing app typography. Use clear, conversational labels and keep mood choices visually distinct when selected.

## Interaction behavior

The listening-room turntable has a subtle, blurred album-art hue aura only while playing, with a static reduced-motion alternative. Its slow drift pauses offscreen or in a hidden document. AmbientWave is integrated beneath the native seek input: a One UI-inspired traveling sine line fills only the played portion; the unplayed track remains quiet. The wave follows stored BPM when available, flattens on pause and remains still with reduced motion. Native seek focus, thumb, keyboard and touch behavior remain intact. No screen, tab or microphone capture is used. These are tempo-paced decorative effects, not audio-amplitude analysis or beat-position synchronization.

The daily journal helper uses the journal-helper-sparkle image launcher and the heading “MetaFor Helper”. Its popover reuses the banner-sunset video with a purple scrim and white text; reduced motion uses the still poster.

### Listening dashboard

The dashboard is a portrait of real Spotify recent history. Preserve the existing Crimson Text/Raleway pair, compact open layout and p5 botanical garden. Raleway owns headings and controls; Crimson Text owns music names, prose and summary numerals. Shared tokens and scrollbars live in `client/src/assets/css/main.css`. Dashboard semantic colors belong to `.dashboard` in `client/src/views/dashboard.vue` and point at the shared theme tokens (the Personality palette), with terracotta play bars; they follow dark mode, and the garden keeps its own sky.

`useSpotifyHistory` owns dashboard loading and retry without playback or search. Spotify access comes from the MetaFor login; `api/spotify.js` remains the shared token/request boundary. `useListeningRoom` belongs to the separate listening-room branch. The page heading is “Your Music at a Glance”, distinct from the “Your Listening Garden” section. The toolbar contains only the weekly/monthly selector; history loads on entry, with Retry history available after a failure.

`spotifyDashboard.js` owns period filtering and aggregation of up to 50 returned plays. All rankings and charts describe only that history; first appearances do not prove new discoveries. Artist collaborations count for each credited artist, but once in total plays. Show counts, not estimated listening minutes. Numeric ranking counts have no per-row units or Play buttons; artist, track and Spotify attribution links remain.

`artworkModel.js` maps the top five artists to deterministically selected visual flower styles. Presets are named for their appearance, never for artists or inferred emotions. Flower size reflects recorded play counts; leaves are decorative. Summary totals use prominent responsive serif numerals with restrained labels.

`ListeningArtwork.vue` lazy-loads p5 in instance mode on a 1000 by 650 canvas. It uses p5 2.x point-wise cubic Bézier vertices. Pause/Animate is the sole garden action. Stop animation when paused, offscreen, hidden or reduced motion is requested; remove observers, listeners and the p5 instance on unmount. Loading and retry reserve the canvas geometry. The artist color key remains beneath the garden.

`ListeningChart.vue` renders actual hourly, daily and repeat-play counts. Mood over time, Emotion profile and Genre mix remain visible but explicitly unavailable until real measurements exist. Never substitute sample values or use the unscoped mood-log collection as personal data. Preserve the two-column desktop grid and stacked mobile layout. The user removed the coverage paragraph, journal shortcut, artwork-rights paragraph and hourly/daily/repeat footnotes.

Live Singapore weather appears inside the garden automatically. `useGardenWeather` owns refresh and cancellation; `gardenWeather.js` draws atmosphere with the garden's paused/reduced-motion clock. No weather readout, location controls, previews or export appear on this dashboard. Provider details and verification live in WEATHER.md.

### Daily mood journal

Its Nuxt UI textarea remains the canonical input and grows with the reflection. Labels, history, and controls retain the app typography. `--font-journal` in `client/src/assets/css/main.css` owns the handwriting stack: locally installed Biro Script, Segoe Print, Bradley Hand, then cursive. Biro Script's downloaded desktop EULA does not grant web redistribution; obtain an appropriate webfont license before bundling a font file. The reference EULA is retained at `../.font-reference/License_EULA.rtf`. Paper decoration is intentionally light even in dark mode; forced-colors mode uses system field colors without texture.

### Listening room

`/listen` is the active listening destination, linked beside Daily Mood; the dashboard remains a retrospective portrait. Preserve the established Crimson Text/Raleway families. The listening room's semantic surface tokens are owned by `.listening-room` in `client/src/views/listen.vue` and point at the shared theme tokens, with brown `#763e32` controls (brand-600 in dark mode). Dynamic `--record-color` comes from the current album cover, lightened for contrast; the fallback is peach `#f0c4a8`.

MetaFor's song-as-feeling ritual becomes a physical record on a Three.js turntable. The turntable is the focal point; the sleeve, controls, and example record shelf remain quiet and functional. Keep the full album cover visible beside the scene. No new art direction was drawn for this application feature; it follows the existing design context and uses the requested taste skill's component guidance. Existing shared navigation keeps its brand accent.

`useListeningRoom` is the canonical playback owner for the room and shared `ListeningDock`. Spotify access comes from the MetaFor login, through short-lived tokens from the server. Playback persists across route changes and the dock provides pause/disconnect access outside the room. The disconnected state is explicitly a silent visual preview. Native buttons and range inputs own keyboard playback, seek and volume; the scene provides pointer shortcuts and optional view rotation. Disable unavailable operations while busy/offline, expose failures as inline alerts, honour reduced motion and provide a WebGL fallback. Search is IME-safe, cancellable and transient; the record shelf contains fixed example tracks, never personalised recommendations. See `SPOTIFY.md` for the auth/storage and HTTP contract.

Listening room refinement (October 2026): Raleway owns the page heading, track heading and controls; Crimson Text owns descriptive text, artist/album metadata and shelf titles. Keep the turntable on a transparent stage with no surrounding text, colored panel, sleeve tab or rotation/reset chrome. The album cover has an image-derived blurred glow and a soft gradient, explicitly requested by the user as an exception to design-taste defaults. Playback uses a compact bank of labeled Previous/Spin-or-Play/Next keys and native, styled seek/volume sliders; disabled sliders stay disabled without Spotify playback. The silent-preview notice sits beside the connection action. Remove mood filters, shelf introductory copy, journal promotion and developer setup disclosure. The shelf shows artwork and track names, with artist names retained for assistive technology. Spotify search appears only while connected; cancellation, IME safety, results, errors, reconnect and disconnect remain owned by useListeningRoom. Album credits remain linked in the footer.


Spotify live-data migration: `useListeningRoom` owns actual Spotify recent history and SDK playback. Disconnected screens show connection/empty states with disabled transport. Search is transient and cancellable; personal data clears on disconnect. Music and artwork link to Spotify.

### Shared action styling

The listening-room connection controls are a restrained exception: a gray Spotify mark when disconnected and a green mark with black waves when connected accompany a two-line service/status label and compact outlined Connect/Reconnect/Disconnect controls. They wrap on narrow screens, retain visible keyboard focus, and use room/theme tokens; Disconnect takes an error tint on hover. Playback and primary actions retain the glossy family.

The listening-room search uses a rounded, subtly inset surface with the shared glass-action button. Focus highlights the entire field with a soft theme-aware ring; the input has no separate rectangular outline. Clear reserves its space when empty, and Search keeps a stable label during loading to avoid movement while typing. Transitions respect reduced motion. Styling remains owned by listen.vue and consumes the existing room/theme tokens.

Application actions use the flat pill family defined in main.css and STYLE.md: terracotta primary, neutral secondary, circular icon, and quiet text variants. Nuxt UI button variants map to these same classes in app.config.ts. Quiz actions, calendar navigation, listening transport/search, dashboard actions, sharing dialogs, navbar controls and landing CTAs reuse these styles. Layout remains owned by each screen; answer cards, calendar dates, privacy switches, drawing swatches and drag handles retain their semantic shapes. Journal and landing mood choices share animated faces and hover/focus reactions through mood-reactions.css. Past entries and the centered, larger story launcher use peach pills; the story play icon hops on hover/focus with reduced motion respected. The landing cassette retains its visual without the drag instruction or tune control. The journal helper close control is red with a white cross.

### Flat button update

Application actions use flat solid fills from the existing theme, without bevels, gradients, blur or drop shadows. Primary actions use brand-600 with white text; secondary and icon actions use the accented surface and theme text. Existing peach, listening-room brown and danger-red variants remain. Keep pill geometry, focus rings, hover/pressed feedback and disabled states. The landing and daily journal emotion choices, drawing tools and color swatches retain their original sculpted 3D treatment. The drawing canvas has no outer panel box; only the drawing surface keeps its boundary. The shared Happy face uses a balanced closed smile and gentle smiling eyes on hover. This supersedes earlier glossy-button guidance.
